# Digest: анализ рабочих переписок в Telegram

[English](README.md) | **Русский**

![CI](https://github.com/ntatarinov/tg-task-bot/actions/workflows/ci.yml/badge.svg)
![Python](https://img.shields.io/badge/python-3.12-blue)
![License: MIT](https://img.shields.io/badge/license-MIT-green)

Бот читает разрешённые рабочие чаты, разбирает обсуждения по темам и присылает ежедневные и
еженедельные дайджесты: что обсудили, что решили, кто что делает и какие вопросы остались открытыми.

## Что умеет

- Сохраняет сообщения разрешённых чатов: автор, время отправки, ответы, ветки, пересылки, правки, медиа.
- Понимает русский, английский и смешанную переписку.
- Объединяет сообщения одной темы, даже написанные в разное время и на разных языках.
- Для каждой темы выделяет предложения, решения, задачи, ответственных, сроки, открытые вопросы, блокеры и следующие шаги.
- Хранит ссылки на исходные сообщения для каждого вывода.
- Не считает предложение решением и не выдумывает исполнителей и сроки: если данных нет, пишет «Не определено».
- Формирует отчёты по расписанию и по команде за любой период, в этот или другой разрешённый чат.

### Что бот не может

Это ограничения Telegram Bot API, а не настройка:

- **Старая история недоступна.** Бот видит только сообщения, отправленные после его добавления в чат. Прошлое можно загрузить из экспорта Telegram Desktop (см. раздел 8).
- **Сообщения других ботов** не приходят.
- **Простой дольше 24 часов.** Telegram хранит неполученные обновления около суток, более старые теряются.
- **Удаление сообщений** не отслеживается: Telegram не сообщает о нём ботам.
- **Ссылки на сообщения** работают только в супергруппах. В обычных группах вместо ссылки показывается номер сообщения.

## Язык

Сообщения бота, дайджесты и сайт задач по умолчанию на английском. Доступен русский.

- **Язык чата.** `/language` (только для администраторов) показывает кнопки; `/language ru` или `/language en` задаёт язык для этого чата. Текущее значение видно в `/settings`.
- **Значение по умолчанию.** `DEFAULT_LANGUAGE=en` в `.env` (`en` или `ru`) действует на все чаты, которые не выбрали свой язык. Его можно изменить и в панели.
- **Текст модели.** Язык чата задаёт и язык того, что пишет модель: названия тем, сводки, элементы. Цитаты остаются на языке оригинала. Уже сохранённый текст при смене языка не переписывается.
- **Сообщения и команды.** Русские и английские сообщения в чате понимаются при любом языке чата. Команды принимают и русские аргументы: `/set_weekly пт` или `/set_weekly fri`, `/digest вчера` или `/digest yesterday`.
- **Меню Telegram.** Меню команд и описание бота в Telegram следуют языку приложения каждого пользователя: по умолчанию английский, для русских клиентов русский.
- **Панель.** Переключатель языка (English / Русский) есть на экране входа и в шапке. По умолчанию английский, выбор запоминается в браузере. В карточке каждого чата есть настройка языка отчётов.
- **Сайт задач** следует языку чата, на нём есть переключатель EN / RU.
- **Командная строка.** Утилиты и скрипты (`install.sh`, скрипты PowerShell, `python -m app.bundle`) пишут по-английски. `python -m app.doctor` следует `DEFAULT_LANGUAGE`.

## 1. Быстрый старт (Windows, локальная SQLite)

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
copy .env.example .env      # затем заполнить, см. разделы 2–4
scripts\start_local.ps1     # запускает модель, обновляет базу, проверяет всё и стартует бота
```

`scripts\start_local.ps1` сам запускает Ollama, обновляет базу (существующую `bot.db` сначала
копирует в `bot.db.bak-<дата>`) и вызывает проверку. Если что-то не готово, он остановится и скажет, что исправить.

Проверить всё без запуска можно командой `python -m app.doctor`. Она сообщает по каждому пункту «ок» или
«ошибка» с подсказкой: токен, режим групп, список чатов, база, модель. Секреты она не выводит.

Подробная инструкция для Windows: [WINDOWS_SETUP.ru.md](WINDOWS_SETUP.ru.md). Сервер и Docker: [DEPLOY.ru.md](DEPLOY.ru.md).

### Панель управления

```powershell
scripts\start_panel.ps1      # откроет http://localhost:8090
```

Нужен пароль в `ADMIN_PANEL_PASSWORD`. На сервере панель открывается через SSH-туннель, см. [DEPLOY.ru.md](DEPLOY.ru.md).

| Раздел | Что там |
|---|---|
| Сводка | Решения, задачи, блокеры и вопросы по чату, отчёт за период. Если стенд не настроен, сверху список шагов |
| 1. Настройка | Токен, модель и чаты; остальные параметры свёрнуты |
| 2. Проверка | Проверка всей системы одной кнопкой и разбор тестовой переписки. Telegram не нужен, рабочая база не затрагивается |
| 3. Перенос | Скачать архив для другого стенда и команды установки |

### Сначала тестовый чат, потом рабочий

1. Создайте группу для теста, добавьте туда бота и напишите любое сообщение.
2. В разделе **Настройка** группа появится как ожидающая. Нажмите **Разрешить** и перезапустите бота.
3. Проверьте работу в тестовой группе.
4. Когда всё устроит, добавьте бота в рабочую группу и разрешите её так же.
5. У тестовой группы нажмите **Запретить** и **Очистить данные чата**.

Чаты изолированы: темы, задачи и отчёты у каждого свои.

Кнопка **Где сейчас бот** спрашивает у Telegram про каждый известный чат. Полного списка чатов бота Telegram
не даёт, поэтому новая группа появляется, когда бот запущен и его туда добавили. Если его добавили, пока он был
выключен дольше суток, удалите его из группы и добавьте снова.

### Смена модели

1. В разделе **Проверка** выберите модель и запустите её на тестовой переписке. Модели можно сравнивать.
2. В разделе **Настройка** нажмите **Выбрать** и перезапустите бота.

Подходит любой сервис с API, совместимым с OpenAI: его можно добавить в разделе **Настройка**.
Внешний сервис нужно подтвердить отдельно: переписка уйдёт за пределы сервера.

### Перенос на сервер

Сначала всё отрабатывается на этом компьютере, потом переносится одним архивом. Его можно скачать
в панели в разделе **Перенос** или собрать командой:

```powershell
.venv\Scripts\python.exe -m app.bundle        # соберёт digest-bot-<дата>.zip
```

Архив содержит код, настройки (`.env`) и копию базы. **Внутри токен и вся переписка**: передавайте его только
по защищённому каналу и удалите после установки. Для кода без данных: `python -m app.bundle --code-only`.

На сервере (Linux, 32 ГБ ОЗУ или больше):

```bash
unzip digest-bot-*.zip -d digest-bot && cd digest-bot
sh install.sh           # бот, панель и модель на этом сервере
sh install.sh cloud     # бот и панель, модель в облаке (нужно LLM_EXTERNAL_ALLOWED=true)
```

Скрипт сам ставит Docker, находит видеокарту NVIDIA, скачивает модель, создаёт пароль панели, обновляет базу и в конце запускает проверку.
Перед запуском бота на сервере остановите его на этом компьютере: с одним токеном два бота работать не могут.

## 2. Подключение Telegram-бота

1. Получите токен у [@BotFather](https://t.me/BotFather) и запишите в `BOT_TOKEN`.
   Для существующего бота: `/mybots` → бот → **API Token**.
2. Отключите Privacy Mode, иначе бот увидит только команды: `/mybots` → бот → **Bot Settings** → **Group Privacy** → **Turn off**.
3. Добавьте бота в группу. Если Privacy Mode менялся, когда бот уже был в группе, удалите его и добавьте снова.
4. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot) и запишите в `ADMIN_USER_IDS`.
5. Запустите бота и отправьте `/chatid` в нужном чате. Запишите ответ в `ALLOWED_CHAT_IDS` и перезапустите бота.

```
ADMIN_USER_IDS=123456789
ALLOWED_CHAT_IDS=-1001234567890,-1009876543210
```

**Пока `ALLOWED_CHAT_IDS` пуст, бот игнорирует все чаты.** Это сделано намеренно: случайно добавленный
в чужую группу бот ничего не сохранит.

## 3. Настройка ИИ-модели

| Вариант | Где обрабатываются данные | Настройка |
|---|---|---|
| Groq (облако, бесплатный тариф) | США, сторонний сервис | Ниже |
| Ollama (локально) | На вашем компьютере | Ниже |
| `mock` | Нигде | Только для разработки, смысл не понимает |

**Groq:**
```
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_API_KEY=gsk_...
OPENAI_MODEL=openai/gpt-oss-120b
LLM_EXTERNAL_ALLOWED=true
```

> ⚠️ `LLM_EXTERNAL_ALLOWED=true` отправляет текст переписки стороннему сервису. Включайте только с
> разрешения владельца данных. Пока значение `false`, сообщения сохраняются и ждут в очереди, наружу
> ничего не уходит, а `/status` показывает причину паузы.
>
> По [документации Groq](https://console.groq.com/docs/your-data) запросы по умолчанию не хранятся,
> но могут логироваться до 30 дней для разбора инцидентов. Чтобы этого не было, включите
> Zero Data Retention в разделе Data Controls консоли Groq.

**Ollama:**
```
LLM_PROVIDER=openai
OPENAI_BASE_URL=http://localhost:11434/v1
OPENAI_API_KEY=ollama
OPENAI_MODEL=gemma4:26b
```

Качество локальной модели надо проверить до использования. Смена модели всегда проверяется так же:

```powershell
.venv\Scripts\python.exe scripts\eval_llm.py --model gemma4:26b --pause 0 --large 1
```

Обязательно включайте большой сценарий (`--large`): `qwen/qwen3.8-27b` проходит короткие переписки,
но теряет отдельные важные сообщения среди болтовни. Запуск бота вместе с моделью на арендованном
сервере описан в [DEPLOY.ru.md](DEPLOY.ru.md).

Скрипт отправляет только синтетические переписки и не читает базу бота.
Результаты последней проверки: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

Groq периодически отключает модели. При старте бот проверяет модель и пишет в лог
`startup.model_unavailable`, если её нет. Если модель недоступна во время работы, сообщения
остаются в очереди и будут обработаны после смены модели.

## 4. Расписание отчётов

По умолчанию ежедневный дайджест приходит в 18:00, еженедельный по пятницам, часовой пояс Asia/Almaty.
Настройки хранятся отдельно для каждого чата.

| Команда | Что делает |
|---|---|
| `/settings` | Показывает настройки, включая язык чата, и кнопки 18:00, 20:00, 21:00, 23:00 |
| `/set_digest_time 19:30` | Произвольное время |
| `/set_timezone Europe/Moscow` | Часовой пояс |
| `/set_weekly пт` | День еженедельного отчёта (`пн`…`вс`, также `mon`…`sun`, например `/set_weekly fri`) или `off` |
| `/set_digest_chat -100…` | Отправлять отчёты в другой разрешённый чат (`here` вернёт в этот) |
| `/digest_on`, `/digest_off` | Включить или выключить отчёты |

Если бот был выключен в момент отправки, отчёт уйдёт в течение `DIGEST_CATCHUP_HOURS` (6 часов).
Ежедневный отчёт охватывает время с конца предыдущего, поэтому разрывов между отчётами нет.

### Отчёт по команде

| Команда | Период |
|---|---|
| `/digest` | Последние 24 часа |
| `/digest today` | С полуночи по времени чата |
| `/digest yesterday` | Вчера |
| `/digest week` | Последние 7 дней |
| `/digest 3d` | Последние N дней |
| `/digest 2026-11-01` | Один день (также `01.11.2026`) |
| `/digest 2026-11-01 2026-11-03` | Диапазон дат |

Слова периода можно писать и по-русски: `/digest вчера`.

Ручной отчёт не отменяет отчёт по расписанию.

## 5. Все команды

**Для всех участников разрешённого чата:** `/start`, `/help`, `/tasks`, `/task <текст>`, `/clarify`,
`/settings`, `/digest`, `/status`, `/chatid`.

**Только для `ADMIN_USER_IDS`:** `/set_timezone`, `/set_digest_time`, `/set_weekly`, `/set_digest_chat`,
`/digest_on`, `/digest_off`, `/language`, `/reanalyze <дней>`, `/purge_history <дней> confirm`, `/pin_dashboard`.

`/language ru` или `/language en` задаёт язык чата, без аргумента показывает кнопки.

`/reanalyze 30` ставит сообщения за 30 дней на повторный анализ. Этим же способом можно разобрать
сообщения, сохранённые старой версией бота. Учтите, что они уйдут в модель.

## 6. Как это работает

```
Telegram ─→ AccessMiddleware ─→ MessageIngestor ─→ БД (очередь pending_analysis)
            отсекает чужие       только сохраняет
            чаты                 без вызова модели

APScheduler, каждую минуту
 ├─ analysis_tick ─→ ConversationAnalyzer ─→ модель (один запрос на пакет)
 │                    └─ проверка ответа ─→ темы, элементы, источники, задачи
 ├─ digest_tick ───→ DigestService ─→ отчёт из проверенных данных ─→ Telegram
 └─ retention_tick ─→ удаление по сроку хранения
```

**Сохранение отделено от анализа.** Медленная или недоступная модель не может потерять сообщение.

**Анализ пакетами.** Модель получает новые сообщения и краткую память о темах, а не всю историю,
поэтому размер запроса не растёт вместе с перепиской. Это нужно и для лимитов: на бесплатном
тарифе примерно 8000 токенов в минуту и 1000 запросов в сутки.

**Модели не доверяем на слово.** Всё, что она вернула, проверяется кодом:

| Проверка | Что происходит |
|---|---|
| Источник | Элемент без существующих исходных сообщений отбрасывается |
| Решение | Без дословной цитаты из источника или с формулировкой «предлагаю», «обсудим» понижается до предложения |
| Исполнитель | Сохраняется, только если назван в источниках или сам написал сообщение |
| Срок | Вычисляется кодом из текста сообщения, от даты сообщения, а не от сегодняшней |
| Проект | Разные проекты не сливаются, даже если модель связала их |
| Инъекции | Сообщения вида «игнорируй инструкции» помечаются, и выводы только на их основе отбрасываются |

Вопрос «кто возьмёт задачу» бот задаёт по шаблону, модель не определяет, что он напишет в чат.
Команды из текста сообщений не выполняются: бот вообще не строит действия на их основе.

**Что будет при сбоях:**

| Сбой | Поведение |
|---|---|
| Модель недоступна | Сообщения ждут в очереди, попытки не расходуются |
| Модель вернула мусор | Пакет уменьшается вдвое; после `ANALYSIS_MAX_ATTEMPTS` сообщения откладываются, и отчёт об этом сообщает |
| Telegram не принимает отчёт | Отчёт не считается отправленным; повтор продолжит с неотправленной части |
| Повторная доставка сообщения | Уникальный ключ (чат, номер сообщения) не даст создать дубль |
| Падение процесса | Пакет применяется одной транзакцией: он либо записан целиком, либо будет обработан заново |

Если часть сообщений не успели обработать, отчёт прямо об этом говорит.

## 7. Безопасность и хранение

- Токены и ключи хранятся только в `.env`, файл не попадает в git. В логах они маскируются.
- В логи не пишется текст сообщений, ошибки базы не содержат параметров запросов.
- Доступ ограничен `ALLOWED_CHAT_IDS` и `ADMIN_USER_IDS`.
- Веб-панель и webhook без секрета закрыты везде, кроме `APP_ENV=local`.

Сроки хранения (0 означает хранить бессрочно, так настроено по умолчанию):

```
MESSAGE_RETENTION_DAYS=90       # удалять сообщения старше 90 дней
RAW_UPDATE_RETENTION_DAYS=7     # удалять сырые данные Telegram старше 7 дней
```

> ⚠️ После включения `MESSAGE_RETENTION_DAYS` старые сообщения удалятся при ближайшем запуске
> задачи (раз в час). Выводы и ссылки на исходные сообщения в Telegram остаются.

`/purge_history 30 confirm` удаляет сообщения чата старше 30 дней. `/purge_history 0 confirm`
удаляет всю историю чата вместе с темами и отчётами; задачи остаются. Удаление необратимо.

## 8. Импорт старой истории

1. В Telegram Desktop: меню чата → **Экспорт истории чата** → формат **JSON**.
2. Загрузите файл:

```powershell
.venv\Scripts\python.exe -m app.importer "C:\path\to\result.json" --chat-id -1001234567890
```

Чат должен быть в `ALLOWED_CHAT_IDS`. Повторный импорт не создаёт дублей. Импортированные сообщения
проходят анализ через очередь и поэтому отправляются в модель. С флагом `--no-analyze` они только сохраняются.
Файл экспорта содержит всю переписку: удалите его после загрузки.

## 10. Веб-панель и метрики

| Адрес | Назначение |

`ENABLE_SCHEDULER=false`, иначе отчёты уйдут дважды. Настройка доступа снаружи описана в [WINDOWS_SETUP.ru.md](WINDOWS_SETUP.ru.md).

Сайт задач следует языку чата, на нём есть переключатель EN / RU.

Все параметры с комментариями перечислены в [.env.example](.env.example).
